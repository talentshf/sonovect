# OS advisory assessment — 0.1.0

This register records the exact maintained source-package versions, primary advisories and scoped dispositions for the v0.1.0 recipes. The CA package repair uses ca-certificates20250419+deb13u1. The63 medium/low/unknown IDs below retain their concrete assessment; raw matches remain visible. TEMP identifiers are Debian-local tracker entries, not assigned CVEs. Actual-image identity and scan evidence must be verified separately for a candidate; source applicability alone is not a completed image scan.

This assessment applies only to maintained Linux amd64 immutable service images, UID 10001, dropped capabilities, no-new-privileges and the documented file-job interface. It is not a whole-image zero-vulnerability assertion, a host assessment or permission to execute untrusted Python, ELF, SQL or regular expressions. Final per-role scan receipts and release qualification are linked from the [current release review](../release-readiness.md).

## Dispositions

- `affected-module-absent`: 4 unique IDs.
- `affected-program-absent`: 29 unique IDs.
- `fixed-by-source-backport`: 19 unique IDs.
- `not-affected-platform-branch`: 1 unique IDs.
- `not-affected-runtime-package`: 1 unique IDs.
- `not-affected-version`: 1 unique IDs.
- `reviewed-service-boundary`: 8 unique IDs.

Nineteen IDs have source repairs: 14 glibc fixes, two SQLite session fixes, one narrow zlib CRC fix and the previously fixed ACL/ncurses IDs. Thirty-three concern absent programs/modules. Three concern a different runtime component, platform branch or version. Eight remain explicitly assessed service-boundary limitations: seven disputed/unfixed glibc issues and corrupt SQLite database/SQL processing. Those eight are **not library fixes** and must be reconsidered if callers or trust boundaries expand. Raw advisories are retained.

Removing shell, Perl, archive and account tools reduces unused code. The exact path/hash removal receipt is retained in each image, alongside package metadata and corresponding modified library sources. It does not remove the scanner's package records. Rebuild instead of mutating service images.

The collector checks real executable/module paths, source versions, nonroot profile, no setid bits, SQLite extension exports and the qualified C++ allocation branch. The audit gate rejects unreviewed findings at **all** severities, changed severity/version, incomplete inventory and missing applicability evidence. Do not reuse dispositions for other images. OS package, Python package and bundled native-library coverage remain distinct.

## Additional checks for the eight retained limitations

The earlier2026-10-22 review fetched the eight Debian records with timestamps and page hashes and checked the then-qualified ten roles. The current13-role image acceptance and2026-10-23 targeted recheck are separate receipts. The following defenses do not relabel a residual library limitation as fixed:

| Advisory | Required trigger and current boundary |
| --- | --- |
| CVE-2010-4756 | Attacker-controlled glob expansion. Uploaded names and job IDs are data; the media interface exposes no glob or pattern execution option. |
| CVE-2018-20796 / CVE-2019-9192 | Arbitrary POSIX regular-expression recursion. The unused grep/egrep/fgrep family is now absent in every final image; the library behavior remains. |
| CVE-2019-1010022 | Stack-guard bypass in combination with a prior stack overflow. This work does not repair arbitrary native memory corruption; unprivileged containers reduce impact only. |
| CVE-2019-1010023 | Running ldd on an attacker-controlled executable. ldd is now absent in every final image; uploads are never executed. |
| CVE-2019-1010024 / CVE-2019-1010025 | Address-layout/thread-stack limitations. These remain residual assumptions, not a verified exploit repair or a promise against memory-corruption chains. |
| CVE-2021-45346 | A crafted corrupt SQLite database plus SQL. Every queue connection now disables extension loading and trusted schema, enables defensive/cell-size checks, and forbids attached databases. The upload interface cannot select or replace the queue database. This is defense in depth, not a library patch. |

Harmless probes on the isolated final API verify rejection of unknown regex/glob/SQL/executable options, SQLite/ELF uploads failing at media decode, and pattern-like/SQL-like job IDs remaining data. These test the exposed service boundary; they do not prove that alternate library callers are immune. Regression tests also verify that a malicious view cannot execute an application function through a trusted schema, that attaching a second database fails, and that protection survives reconnection.

### Rechecking retained limits

The eight upstream records were reviewed again on2026-10-23; their retained semantic snapshots are bound by [this baseline](retained-advisories.json). No directly applicable fixed version was listed. The accepted images separately passed another check of removed entry points, unprivileged execution and SQLite controls. This targeted verification is not a new full image scan.

Before a release or dependency update, run:

```sh
python scripts/check_retained_advisories.py --output /tmp/sonovect-advisory-review.json
```

The tool fetches the official Debian records, checks exact retained-ID and source-version coverage, and fails on changed advisory text or incomplete retrieval. For a disconnected review, `--pages DIRECTORY` accepts previously fetched `CVE-ID.html` pages; record their acquisition time separately. It never changes the baseline or suppresses scanner findings. A failed check requires reviewing the upstream change and current applicability before an explicit baseline revision. An unchanged receipt proves advisory consistency only.

Reassess the actual callers and rerun image probes when adding regex/glob input, executable handling, SQL/database imports, extensions, alternate decoders, privileges or new model code. Continue the actual-image OS/Python/native-library checks independently. The eight limitations remain disclosed until an applicable repair or verified code removal changes the assessment. No scheduled process or new service is installed by this check.
